## ❌ Отклонить

### A1. §9.2 — «`MpvRenderContext` — вымышленный класс, Render API в `python-mpv` нет»

**Вердикт: неверно.** Проверено прямым чтением исходника пакета.

```
$ pip download python-mpv --no-deps    →  python_mpv-1.0.8-py3-none-any.whl
$ grep -n "MpvRenderContext" mpv.py
2157:class MpvRenderContext:
```

Фактическая сигнатура в `python-mpv` 1.0.8:

```python
class MpvRenderContext:
    def __init__(self, mpv, api_type, **kwargs)      # строка 2157
    def render(self, **kwargs)                        # строка 2201
    def update(self) -> bool                          # mpv_render_context_update
    def report_swap(self)
    # update_cb — property через __setattr__, строка 2173
```

Поддерживаемые параметры (`MpvRenderParam.TYPES`, строка 225) включают
`api_type`, `opengl_init_params`, `opengl_fbo`, `flip_y`, `advanced_control`,
`next_frame_info`, `block_for_target_time`.

Код из v1.0 —
`MpvRenderContext(mpv, "opengl", opengl_init_params={...})`,
`ctx.update_cb = ...`, `ctx.render(flip_y=True, opengl_fbo={...})`
— **совпадает с реальным API дословно**.

**Последствия принятия ошибочной правки:** ~200 строк лишней ctypes-обёртки,
дублирующей готовый и оттестированный код, плюс ложный риск R3a в реестре рисков.

**Решение:** вернуть формулировку v1.0. Риск R3a переформулировать (см. 🟡 B7) —
зерно истины в нём есть, но не то, которое заявлено.

### A2. §11.3 — «`metadata=print` не даёт `pts_time`, нужен `showinfo`»

**Вердикт: неверно в основной части, верно в побочной.**

`metadata=print:file=-` печатает заголовок кадра в формате
`frame:N pts:N pts_time:S` и затем строки `lavfi.scene_score=...`.
`pts_time` там **есть**, и он идёт в stdout — что парсится существенно надёжнее,
чем `showinfo`, пишущий в stderr вперемешку с логом ffmpeg.

**Что в правке верно:** без управления кадровой синхронизацией `select` может
дублировать метки. Но `-vsync 0` в ffmpeg ≥ 6 объявлен устаревшим.

**Решение:** оставить `metadata=print:file=-`, добавить `-fps_mode passthrough`:

```bash
ffmpeg -hide_banner -nostats -i input.mkv \
  -filter:v "select='gt(scene,0.35)',metadata=print:file=-" \
  -fps_mode passthrough -an -sn -f null -
```

### A3. §12.2 — «корректная сигнатура `const char* codepage`»

**Вердикт: неверно в детали, безвредно по сути.**
В `ass.h` объявлено `char *codepage` (без `const`). В `ctypes` и то и другое —
`c_char_p`, поэтому на код это не влияет.

**Что в правке верно и нужно сохранить:** передавать `None` (== NULL), а не строку,
и задокументировать это в обёртке.

**Решение:** убрать утверждение про `const`, оставить указание про `None`.

---

### A4. §12.2 — «ctypes освобождает GIL только при `use_errno`»

**Вердикт: неверно.** `ctypes.CDLL` освобождает GIL на время каждого внешнего
вызова **по умолчанию**; не освобождает `ctypes.PyDLL`. Флаг `use_errno` управляет
сохранением `errno`, а не GIL.

**Что в правке верно и важно:** сам вывод — libass вызывать только из main-потока,
`ass_render_frame` не потокобезопасен относительно одного `ASS_Renderer`.

**Решение:** сохранить вывод, заменить обоснование. Если понадобится гарантия
неперемежающихся вызовов — это делается собственным `threading.Lock` вокруг
рендерера, а не выбором флагов ctypes.

## ✅ Принять — верно и ценно

### B1. §5.7 — `TimeIndex.active_at` без проверки `_ends[i]`

**Настоящий баг v1.0.** Префиксный максимум `max_end_prefix[i] > t` — это только
условие раннего выхода из цикла; из него не следует, что событие `i` активно.
Без проверки `_ends[i] > t` метод возвращал ложные срабатывания.

Исправлено в прототипе (`core/index.py`), покрыто property-тестом на случайных
интервалах против наивной O(n) реализации.

### B2. §5.4 — `RGBA`, `ScriptInfo`, `Attachment` использовались без определения

**Верно.** Типы фигурировали в сигнатурах, но не были описаны — API из Приложения B
не собирался. Определения добавлены.

### B3. §5.4 — не хранить байты шрифта в документе/undo/журнале

**Верно и архитектурно важно.** Шрифт 10–20 МБ, размноженный по дельтам undo и
JSONL-журналу восстановления, раздувает и память, и автосейвы. Контент выносится в
кэш-файл, в модели остаётся `data_path`.

### B4. §12.4 — шейдер не premultiplied при premultiplied-блендинге

**Настоящий баг v1.0.** `vec4(color.rgb, a)` с `glBlendFunc(GL_ONE, GL_ONE_MINUS_SRC_ALPHA)`
даёт переосветление. Корректно: `a = color.a * tex.r; frag = vec4(color.rgb * a, a)`.

*Уточнение:* фраза правки «альтернатива даёт тёмную кайму» неточна — вариант
straight-alpha с `GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA` математически корректен,
просто хуже при фильтрации и при рендере в промежуточный FBO. Формула из правки
верна, обоснование стоит смягчить.

### B5. §6.2 vs §19.2 — противоречие «снимки 64 МБ» vs «undo хранит дельты»

**Верно.** Реальное внутреннее противоречие v1.0. Формулировка правки корректна.

### B6. §14.5 — линейная синхронизация без защит

**Верно.** При `A.start == B.start` — деление на ноль; при `T2 <= T1` — отрицательный
масштаб. Гарды нужны. Реализованы в прототипе (`services/sync.py` заложен, команда
`LinearSyncCommand`).

### B7. §10.2 — ключ кэша пиков без `audio_stream_index` и без версии экстрактора

**Верно, и `audio_stream_index` — лучшая находка всей правки.** Без него смена
аудиодорожки молча отдаёт волну от другой дорожки. Версия формата тоже нужна.

*Про `sha1 → sha256`:* здесь нет противника, коллизия невозможна на практике —
это косметика. Но длинно-префиксированная сериализация полей вместо конкатенации
строк — верно по существу.

### B8. §10 — случай «в файле нет аудиодорожки»

**Верно.** Дыра в v1.0: поведение не было описано. Деградация вместо ошибки — правильно.

### B9. §13.1 — `ViewTransform` игнорирует `rotation`

**Верно.** В v1.0 `rotation` присутствовал в `VideoParams`, но нигде не использовался;
вертикальные видео 90°/270° сломали бы всю геометрию.

*Уточнение:* предписание «композитор поворачивает кадр mpv» лишнее — mpv поворачивает
сам (`--video-rotate=no` отключает). Нам нужно лишь поменять местами w/h **до** расчёта
`video_rect` и отдать libass уже display-ориентацию.

### B10. §17.1 — `overlap` должен быть предупреждением, а не ошибкой

**Верно.** Перекрытие событий полностью валидно в ASS (libass рендерит оба по `Layer`).
Классифицировать как ошибку неправильно.

### B11. §16 — конфликты горячих клавиш

**Верно, конфликты были настоящие:** `Ctrl+Shift+S` = «Разбить событие» **и**

*Но выбранное разрешение спорное* — см. 🟡 C1.

**Верно.** v1.0 говорил «сериализуется в append-only», не отвечая на вопрос

### B13. §22.2 — «read-only view» не обеспечивается соглашением

**Верно по сути.** На чистом Python `SubtitleDocumentView` как ссылка на живой документ

*Но предписание спорное* — см. 🟡 C4.

**Верно.** Qt 6 Essentials + ffmpeg + libmpv + Python-рантайм не помещаются в 95 МБ.
Разделение на «установленный размер» и «размер загрузки» — правильный подход.

## 🟡 Принять с корректировкой

### C1. §16 — как именно разрешать конфликты клавиш

Правка увела **«Сохранить как» на `Ctrl+Alt+S`**. Это ломает универсальную конвенцию
(Word, VS Code, GIMP, Photoshop, Blender — везде `Ctrl+Shift+S`).

**Лучше наоборот:** `Ctrl+Shift+S` оставить за «Сохранить как», а «Разбить событие»
перевести на `Ctrl+Shift+K` (по аналогии с «разрезать» в редакторах). Аналогично
«Сбросить `\pos`» → `Ctrl+Shift+0`, палитра → `Ctrl+P` (как в правке — верно).

### C2. §11.2 — удаление `skip_frame = "NONKEY"`

Правка верна: `skip_frame` влияет на декодирование, а `demux()` кадры не декодирует,
поэтому строка была бесполезна. Но обоснование стоит дополнить: строка не просто
бесполезна — она вводит в заблуждение, создавая впечатление, что происходит
декодирование. Удалить — да.

### C3. §13.4 — округление `\pos` до целых при коммите

Правило разумное, но **условие нужно уточнить**: округлять только если значение
пришло из жеста мыши. Если пользователь ввёл `1920.5` вручную в поле — сохранять как
есть. Иначе поле ввода будет «съедать» дробную часть, что выглядит как баг.

### C4. §22.2 — глубокий immutable-снимок документа для плагина

Правка требует копировать все события/стили **на каждый вызов** `api.document()`.
На 20 000 событий это ~50 мс и мусор в GC — неприемлемо для плагина, дергающего API в цикле.

**Лучше:** класс-обёртка `DocumentView` с `__slots__`, блокирующим `__setattr__`,
отдающий `MappingProxyType` для словарей и **ленивые кортежи-представления** для списков
(копия создаётся при первом обращении и мемоизируется по `_revision` документа).
Тест `test_plugin_cannot_mutate` — принять как есть, он проверяет свойство, а не реализацию.

### C5. §18.2 — правило про блокирующие вызовы

Уточнение верное (исходное «запрет на импорт `time.sleep`» и правда грубое и
неполное). Но «кастомный ruff-плагин» — избыточно для v1.0: ruff поддерживает
`flake8-banned-api` через `lint.flake8-tidy-imports.banned-api`, чего достаточно для
`time.sleep` / `subprocess.run`, а вызовы методов (`QThread.msleep`) ловятся
простым правилом `AST`-теста в `tests/unit/test_no_blocking_in_ui.py`.
Дешевле и без внешнего плагина.

### C6. §2 — «Python 3.12 (LTS-ветка проекта)»

Правка справедливо отмечает, что термина «LTS» у CPython нет.

**Но обе версии теперь устарели по существу.** Проверено:

```
PySide6            → pyside6-6.11.2-cp310-abi3-win_amd64.whl   ✅ работает на 3.14
av                 → av-18.1.0-cp311-abi3-win_amd64.whl        ✅ stable ABI
numpy              → numpy-2.5.3-cp314-cp314-win_amd64.whl     ✅ нативное колесо
pysubs2            → pysubs2-1.9.0-py3-none-any.whl            ✅
charset-normalizer → charset_normalizer-3.5.1-cp314-…whl       ✅
```

Все зависимости ставятся на **Python 3.14**. Риск R1 закрыт, понижение до 3.12 не нужно.

**Решение для v1.2:** целевая версия — **3.13** (устойчивое большинство колёс),
`requires-python = ">=3.12,<3.16"`, CI-матрица `3.12 / 3.13 / 3.14`, разработка на
3.14 разрешена. R1 переводится в закрытые.

### C7. §27 — риск R3a

Формулировка («`python-mpv` заброшен») построена на ошибочной посылке A1.
Реальный риск другой и он существует: **`python-mpv` — однофайловый пакет с одним
мейнтейнером; ABI libmpv может измениться быстрее, чем выйдет обновление**.

Переформулировать: *«Отставание `python-mpv` от новой libmpv»*, снижение — пин
`libmpv >= 0.37,<0.40` + вендоринг конкретной версии DLL + smoke-тест Render API в CI.
Собственная обёртка — аварийный план, а не основной (в отличие от того, что предлагала правка).

## Дополнение: что подтвердилось после вендоринга библиотек

Библиотеки установлены (`libmpv 2.5`, `libass 0.17.5`), спайк прошёл. Это
позволило проверить спорные пункты аудита не рассуждением, а запуском.

### Подтвердилось отклонение A1 (`MpvRenderContext` существует)

Обёртка `python-mpv` работает ровно так, как было записано в v1.0:

```python
ctx = mpv.MpvRenderContext(player.raw, "opengl",
                           opengl_init_params={"get_proc_address": proc})
ctx.update_cb = ...
ctx.render(flip_y=True, opengl_fbo={"fbo": ..., "w": ..., "h": ...})
```

Видео декодируется через **nvdec**, кадр приходит в FBO Qt. Собственная
ctypes-обёртка, которую предлагала правка, не понадобилась.

### Подтвердилось отклонение A3/A4 частично

`ass_read_memory` вызывается с `codepage=None` — как и было записано.
Вся работа с libass идёт из главного потока, как предписывала правка;
обоснование про GIL к делу отношения не имело, но вывод был верным.

### Уточнение к B4 (premultiplied alpha)

На практике оверлей рисуется не сырым GL-шейдером, а через `QPainter`
(`QImage.Format_Alpha8` + `CompositionMode_SourceIn`), поэтому вопрос
premultiplied-блендинга в прототипе не возникает. Замечание остаётся
верным для варианта с собственным шейдером, если к нему вернуться ради
производительности.

### Новое, чего не было ни в одной версии документа

Три ограничения выяснились только на живом коде и внесены в `docs/MODULES.md`:

1. перекрытый `QOpenGLWidget` перестаёт отдавать кадр — оверлей обязан
   рисоваться внутри `paintGL`;
2. смешение рендера mpv и `QPainter` без `beginNativePainting()` роняет
   процесс внутри драйвера;
3. файл нельзя отдавать плееру раньше создания GL-контекста, иначе mpv
   остаётся без аппаратного декодирования.

Ни одно из них не следует из документации mpv или Qt — все три найдены
воспроизведением сбоя и бисектом.
