# Сборка

## Одним файлом

```
python build/release.py
```

Собирает бинарник и кладёт его вместе с запиской для проверяющего в папку
`SubtitleEditor/Сборка/` — рядом с проектом, но вне его дерева: `dist`
перезаписывается при каждой сборке и лежит среди исходников, ходить туда
человеку, который просто хочет запустить программу, незачем.

Копирование идёт через временное имя с переименованием. Если предыдущая версия
запущена, копирование поверх упало бы на середине и оставило нерабочий файл
вместо прежнего рабочего; так вместо этого выводится понятная просьба закрыть
программу.

`--no-build` раскладывает уже собранное, `--output ПУТЬ` меняет папку.

Только сборка, без раскладки:

```
python -m PyInstaller --clean --noconfirm build/onefile.spec
```

Результат — `dist/SubtitleForgeStudio.exe`, ~144 МБ. Запускается из любого
каталога, ничего не требует установленным: Python, Qt, libmpv и libass лежат
внутри.

Перед сборкой нативные библиотеки должны быть разложены:

```
python build/vendor_libs.py --check
```

## Что внутри и почему так много

| Часть | Размер | Комментарий |
|---|---|---|
| `libmpv-2.dll` | 120 МБ | сборка shinchiro статически линкует весь FFmpeg |
| остальные нативные | 14 МБ | libass, freetype, harfbuzz, fontconfig, glib и их зависимости |
| PySide6 + Qt | ~25 МБ | после вычистки неиспользуемых модулей |
| Python и пакеты | ~15 МБ | вместе с PyAV и NumPy |

Список `excludes` в `onefile.spec` убирает то, что PySide6 тянет по умолчанию:
QtWebEngine, Qt3D, QtMultimedia, QtQml и прочее. Приложению нужны только
QtCore, QtGui, QtWidgets и QtOpenGLWidgets. Без этого списка бинарник
получается примерно вдвое больше.

## Цена одного файла

В режиме onefile загрузчик при **каждом** запуске распаковывает содержимое во
временный каталог. Из-за 134 МБ нативных библиотек это 5–8 секунд до появления
окна. Это свойство формата, а не недоработка сборки.

Если старт важнее числа файлов, соберите каталогом — он стартует за доли
секунды: замените в `onefile.spec` `EXE(...)` на пару `EXE`/`COLLECT`
(стандартная схема PyInstaller) либо соберите без спеки:

```
python -m PyInstaller --noconfirm --windowed --name SubtitleForgeStudio build/entry.py
```

## Проверка собранного

```
dist/SubtitleForgeStudio.exe --version
dist/SubtitleForgeStudio.exe --selftest
```

`--version` печатает версии компонентов и **найденные пути** к libmpv и libass —
это первое, что нужно смотреть, если приложение не видит нативных библиотек.
`--selftest` прогоняет ядро на синтетических данных без GUI.

## Диагностика

| Приём | Зачем |
|---|---|
| `SFSTUDIO_HANG_DUMP=25` | печатает стек всех потоков, если приложение зависло; отладчик к onefile подцепить трудно, а стек отвечает сразу |
| `QT_DEBUG_PLUGINS=1` | показывает, какие плагины Qt загрузились и откуда |
| `SFSTUDIO_LIBMPV` / `SFSTUDIO_LIBASS` | прямой путь к библиотеке в обход поиска |

Сборка **оконная** (`console=False`): чёрное окно терминала рядом с
приложением пользователю не нужно. Диагностика при этом не теряется —
`build/entry.py` уводит `stdout`, `stderr` и сообщения Qt в журнал, путь к
которому печатает `--version`:

```
%APPDATA%\SubtitleForge\config\logs\sfstudio.log
```

В оконной сборке PyInstaller `sys.stdout` равен `None`, и любой `print`
падает с `AttributeError`. Поэтому потоки подменяются **до** того, как что-то
попробует напечататься, — иначе приложение упало бы на первом же сообщении.

Сообщения Qt идут мимо `sys.stderr`, поэтому для них ставится собственный
перехватчик. К каждому уникальному сообщению он добавляет стек Python: голое
«QFont::setPointSize: Point size <= 0 (-1)» без места вызова бесполезно —
непонятно, какой из десятка виджетов его вызвал.

## Две ловушки, на которые уходит время

**Кодировка.** Замороженный интерпретатор не подхватывает UTF-8 для `stdout`,
а консоль Windows остаётся в кодовой странице 866 — весь русский вывод
превращается в мохибейк. `build/entry.py` чинит это до первого вывода:
`SetConsoleOutputCP(65001)` и `reconfigure(encoding="utf-8")`.

**Шрифты и эмодзи.** Глифы вроде `▶` и `⏮` в собранном виде превращались в
пустые прямоугольники, а `QFont` под них давал предупреждение о нулевом
кегле. Иконки транспорта поэтому рисуются кодом (`ui/icons.py`), а не берутся
из шрифта.

**Два процесса.** В onefile загрузчик порождает дочерний процесс, и Python со
всеми окнами живёт именно в нём. Если проверять сборку скриптом, окно нужно
искать по дочерним PID: у родительского видны только консоль и служебное
`PyInstaller Onefile Hidden Window`. На этом легко сделать ложный вывод, что
GUI не поднимается.

## Видеокарта в собранном виде

**`os.add_dll_directory` не решает задачу.** Пакеты `nvidia-cublas-cu12` и
`nvidia-cudnn-cu12` кладут библиотеки в `site-packages/nvidia/*/bin` —
каталог, которого нет ни в PATH, ни в путях поиска Windows. Добавленные
через `add_dll_directory` каталоги просматриваются только при загрузке с
флагами `LOAD_LIBRARY_SEARCH_*`, а CTranslate2 зовёт `LoadLibrary` по голому
имени файла. Итог — `Library cublas64_12.dll is not found`, молчаливый откат
на процессор и прогресс, замерший на десятой доле.

Лечится явной загрузкой по полному пути (`ctypes.WinDLL`): загруженная DLL
попадает в таблицу модулей процесса, и поиск по имени находит уже открытую
копию. Ссылки на дескрипторы приходится хранить — иначе их закроет сборщик
мусора. Порядок загрузки — порядок зависимости: `cublasLt` раньше `cublas`.

**`get_supported_compute_types("cuda")` отвечает не о том.** Он говорит о
возможностях карты, а не о наличии библиотек: на машине без cuBLAS уверенно
перечислял float16 и int8. Проверять готовность нужно попыткой загрузить
библиотеку.

**Нужен только cuBLAS.** cuDNN ставится тем же набором пакетов, но для
Whisper CTranslate2 к нему не обращается — проверено запуском без него.
0,7 ГБ против 2 ГБ, и это разница между «можно положить рядом с программой»
и «нельзя».

**Внутрь однофайловой сборки библиотеки не кладутся.** 0,7 ГБ распаковывались
бы во временный каталог при каждом запуске, включая запуски тех, у кого
видеокарты нет. `build/release.py` кладёт их в папку `cuda` рядом с exe;
`_cuda_search_roots()` ищет её сама, путь переопределяется переменной
`SFSTUDIO_CUDA_DIR`.

**Карта новее библиотеки — не приговор.** RTX 5070 Ti (sm_120) новее сборки
CTranslate2 4.8.2, и ядра драйвер собирает из PTX при первом запуске:
6 секунд, затем из кэша. Поэтому `CUDA_CACHE_MAXSIZE` поднимается до 2 ГБ —
кэш по умолчанию мал, и большая библиотека вытесняет оттуда сама себя.

## Лицензионное замечание

Используемая сборка libmpv включает GPL-компоненты FFmpeg (риск R6 в
`docs/MODULES.md`). Для распространения нужна LGPL-сборка. На разработку и
тестирование это не влияет.
