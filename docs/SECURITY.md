# Аудит безопасности

Что проверялось: выполнение произвольного кода, обращение с данными из чужих
файлов и из сети, поиск и загрузка библиотек, запуск сторонних программ.

Модель угроз здесь простая. Программа открывает **файлы субтитров, которые
человек скачал со стороны** (opensubtitles, чужой перевод, файл от заказчика),
и **скачивает по сети** модели, библиотеки и один исполняемый файл. Всё это —
недоверенные данные. Плагины стоят особняком: их код исполняется по замыслу.

---

## Найдено и исправлено

### 1. Текст реплики попадал в подсказку как разметка

**Где:** `ui/timeline.py` (подсказка на таймлайне), `ui/event_table.py`
(подсказка в колонке текста).

Qt решает сам, разметка перед ним или обычный текст: строка, похожая на HTML,
показывается **как HTML**. Проверено: `QLabel` с `<img src="…">` принимает
размеры картинки, то есть ресурс действительно загружается.

Реплика вида `<img src="\\сервер\общий\точка.png">` в скачанном файле означала
поход Windows на этот сервер с автоматической аутентификацией — то есть утечку
NetNTLM-хеша по наведению мыши. Ссылка `<a href>` в подсказке — из того же
набора.

**Исправление:** `ui/safe_text.py`, функция `plain_tooltip`. Текст, который Qt
может принять за разметку, экранируется и оборачивается в `white-space:
pre-wrap` — переносы строк сохраняются, теги остаются буквами. Обычный текст
проходит без изменений, чтобы не платить за каждое движение мыши.

### 2. Загрузка cuBLAS по голому имени файла

**Где:** `services/asr/engines/faster_whisper.py`, `_cublas_ready`.

`ctypes.WinDLL("cublas64_12.dll")` без пути запускает поиск по правилам
Windows, а в них входит **текущий рабочий каталог**. Программу нередко
запускают из папки с чужими материалами; положенная туда `cublas64_12.dll`
выполнилась бы при первом же открытии окна распознавания.

**Исправление:** файл ищется по каталогам `CUDA_PATH` и `PATH` (`_find_in_path`)
и загружается по полному пути. Относительные записи в `PATH` — то есть снова
текущий каталог — пропускаются.

Остальные библиотеки CUDA уже грузились по полному пути; это было сделано
раньше по другой причине (CTranslate2 не видел `add_dll_directory`).

### 3. Точка входа плагина могла указывать наружу

**Где:** `plugins/loader.py`.

`entry` берётся из манифеста, а манифест пишет автор плагина. Путь
`../../скачанное.py` заставил бы программу выполнить файл, о котором человек
думал как о данных.

От вредоносного плагина это не спасает — его код и так исполняется, — но
выполнять посторонний файл вне каталога плагинов программа не должна.

**Исправление:** путь приводится к абсолютному и проверяется на принадлежность
папке плагина; иначе плагин помечается сломанным с внятной причиной.

### 4. Скачанное не сверялось с контрольной суммой

**Где:** `services/accel/libraries.py`.

Указатель PyPI отдаёт `sha256` каждого файла — и он не использовался.

**Исправление:** сумма считается на лету при скачивании и сверяется; при
расхождении файл удаляется, а не остаётся обрубком, который потом сойдёт за
установленную библиотеку. Это не подпись (обе величины из одного источника), но
ловит и повреждение при передаче, и подмену на зеркале.

### 5. Адрес загрузки брался из ответа сервера без проверки

**Где:** `services/accel/libraries.py` (PyPI), `services/accel/binaries.py`
(GitHub).

Адрес приходит строкой в JSON и вести может куда угодно. Для whisper.cpp это
особенно неприятно: скачанный файл потом **запускается как программа**.

**Исправление:** проверяются схема (`https`) и хост по списку — файлы PyPI
лежат на `files.pythonhosted.org`, файлы выпусков на доменах GitHub.

### 6. Амперсанд в именах из файла

Имя актора или дорожки Qt толкует как мнемонику: «Иван & Марья» показывалось бы
как «Иван  Марья». Не безопасность, а корректность отображения чужих данных —
`safe_text.menu_label`.

## Проверено, оказалось в порядке

| Что | Итог |
|-----|------|
| `eval`, `exec`, `compile`, `pickle`, `marshal`, `yaml.load` | не встречаются |
| `os.system`, `shell=True` | не встречаются; ffmpeg и whisper.cpp запускаются списком аргументов с абсолютным путём |
| Распаковка архивов | `extractall` нигде нет. Библиотеки достаются по нашему списку имён, путь из архива не участвует; архив whisper.cpp проверяется на выход за каталог (`is_relative_to`) |
| Проверка сертификатов TLS | нигде не отключалась |
| Чтение проекта (`.sfproj`) | zip читается в память, файлы наружу не пишутся |
| Шаблон метки говорящего | всё, кроме подстановок, проходит через `re.escape`; ошибка компиляции перехвачена |
| Поиск libmpv и libass | переменная окружения → каталог внутри пакета → системные пути; загрузка по полному пути |
| `shutil.which` для ffmpeg | в Python 3.14 текущий каталог не просматривается — проверено запуском |
| mpv | `ytdl=no`: путь из проекта не превращается в сетевую загрузку |
| Определение кодировки | эвристика по байтам, ничего не исполняет |
| Автообновление, телеметрия | отсутствуют |

## Принято осознанно

**Плагины исполняют произвольный код.** Это их назначение: песочницы нет и не
планируется. Смягчение — не техническое, а честное: список выключен, пока его
не включат в настройках, каждый плагин можно выключить по отдельности, а
поломка плагина не роняет программу. Ставить плагины следует так же
осмотрительно, как любую программу.

**Путь к видео в проекте может вести в сеть.** Проект хранит путь к
видеофайлу — в том числе `\\сервер\общий\фильм.mkv`. Открывать его и есть
назначение проекта, а путь виден в заголовке окна.

**Файл проекта может быть zip-бомбой.** Распаковка идёт в память, и очень
большой вложенный файл съест память. Файл открывает сам пользователь, ущерб
ограничен собственным сеансом.

## Регрессионные тесты

`tests/unit/test_security.py` — 23 проверки. Каждая закрывает конкретную
находку, а не «безопасность вообще». Работоспособность проверена возвратом
уязвимости: с откаченным исправлением падают тесты подсказок, точки входа
плагина, контрольной суммы и поиска библиотеки.
